5. 실패했을 때의 흐름 (REV3 후처리)

노션 기록 실패 (장애·오류) │ ① 기록한 값 전부 자동 롤백 (돈 데이터 오염 0) ② 09 로그: 오류·ERROR │ ③ 01_RAW: 반영실패 유지 ④ 11_검토큐: 대기/재반영대기 유지 → 계속 보임 ✅ ▼ ⑤ [반영] 재클릭 → 성공 시 위 8단 사건 그대로
잘못 '처리'로 닫힌 옛 건 발견 (예: A업체) │ ★ REV4 : 웹앱 검토큐 [🛠 반영실패 후처리 복구] 또는 시트 메뉴 [반영실패 후처리 복구 (REV3)] 1회 │ → 09 검증=OK 없는 '처리' 건만 골라 ▼ 상태=재반영대기 부활 + RAW=반영실패 복원 → 검토큐에서 [반영]

6. 노션 연계 (직접 확인하는 법)

  1. 노션에서 확인 — 「푸로찜 입출고 DB」에서 해당 거래처 페이지를 열어 입금일자 속성에 날짜가 찍혔는지 봅니다. 이것이 최종 목적지입니다.
  2. 시트에서 확인 — 03_노션_납품RAW D열(입금일자) = 노션의 거울 · 09_노션_반영로그 = 기록 시도 증거 · 22_입금일자_연동이력 = 전수 감사표.
  3. 웹앱에서 확인 — 「노션 입금일자」탭 요약의 노션 기록 완료 건수 · 「기록 검증」탭에서 수신ID 1건의 3값(RAW·미러·09) 나란히 대조.
  4. 순서 원칙 — 웹앱 탭은 전부 읽기 전용 표시 계층이고, 값의 원본은 시트+노션입니다. 화면이 이상해 보이면 ① 01_RAW 매칭상태 → ② 09 검증열 → ③ 노션 페이지 순서로 따라가면 100% 원인을 찾을 수 있습니다.
